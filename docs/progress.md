## Phase 0 — Foundation · **done (local)**, 6 Nov 2026

**Goal:** a working monorepo, CI, local Supabase, Modal skeleton and agent rules.

### What shipped

**Repo and tooling**

- pnpm 10 workspace (`apps/web`, `packages/*`), TypeScript strict everywhere
  (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), ESLint 10 flat config,
  Prettier, Vitest 5, Playwright 1.65, Node 22 in CI. Versions and the two deliberate
  pins are in `docs/decisions/ADR-0001-stack.md`.

  durations, inline easing curves and emoji are all errors inside
  `apps/web/src/{ui,features}`.

**apps/web**

- Vite 8 + React 19 + Tailwind v4 + vite-plugin-pwa.
- `src/styles/tokens.css` is §12.2 copied verbatim (and Prettier-ignored, so it stays
  diffable against the plan). Self-hosted WOFF2 for Bricolage Grotesque, Instrument Sans
  and JetBrains Mono — variable axes, subset per unicode-range, regenerated by
  `pnpm fonts:fetch`.

  (N1, N5, N7, N8, N12) are listed at `/dev/sheets`; `/dev/ui`, `/dev/states` and

- `src/app/flags.ts`: the seven §13 feature flags, all `false` in V1, with `?flags=all`
  for the visual tests and `?demo=1` for demo mode.
- PWA manifest with the `/check` share target, `theme_color #0E1726`,
  `background_color #F6F7F9`, `display: standalone`, and an app-shell service worker.
- Cloudflare Pages `_redirects` and `_headers` (CSP, HSTS, `Permissions-Policy:
camera=(self)`, immutable asset caching).

**packages/shared**

- The locked vocabulary from §9 (every Postgres enum) plus the §11.3 confidence banding,
  with the rule that a percentage is only ever shown once a brand × category has ≥ 200
  outcomes **and** the model is calibrated **and** the flag is on.

**apps/worker (Modal)**

- `tryitout_worker/api.py` holds the FastAPI app (no Modal import, so it is testable);
  `app.py` wraps it for `modal serve` / `modal deploy`, scale-to-zero, secret `tryitout`.
- `GET /health` behind Supabase JWT verification against the project JWKS. Asymmetric
  algorithms only — an HS256 token signed with a leaked anon key is refused.
- ruff + mypy strict + 17 pytest tests.

**supabase**

- `supabase init`, `config.toml` set for the project: anonymous sign-ins on, email and SMS
  providers off (§19 step 2.3), redirect URLs for local dev.
- `migrations/0000_health_check.sql` and the public `health` Edge Function, which is what
  the daily keep-alive calls so a Free project never pauses (§19 step 8).

**CI and agents**

- `.github/workflows/ci.yml`: install, lint, typecheck, unit, build, licence check,
  Playwright e2e and visual, plus a worker job on Python 3.11 and a job that fails a PR
  which changes `design/screens` without the `design-change` label (§17.4).
- `health.yml`, `deploy-functions.yml`, `deploy-worker.yml` — each skips cleanly until its
  secrets exist.
- `AGENTS.md`, `CLAUDE.md`, `.claude/agents/*` and `.claude/commands/*` copied verbatim

### What the pixel diff found

Chasing 4.1 from 2.64% to 1.18% turned up three real errors that reading the code would
not have shown, which is the argument for keeping the gate tight:

- The promo card's icon was 26 px where the design draws 36, which made the card 10 px
  short and moved everything under it.
- The desktop sidebar used the 30 px tape mark instead of the 32 px app icon. They are
  two different marks in §12.4 and it is easy to reach for the wrong one.
- The table header was set in the 11 px `micro` step; §12.4's DataTable says 12 px. That
  one pixel of header height put all eight table rows out.

A calibration made it worth hunting rather than writing off as rendering noise: shifting
the design against itself by one pixel costs 1.52% on 4.1, so a 2.64% diff was provably
more than a whole-page one-pixel shift.

### What CI found that local runs did not

Two things, both worth keeping in mind for later phases:

- **Platform text rendering.** The same commit that is 0.19% on macOS is 2.61% on Linux.
  ADR-0005 moves the comparison to macOS rather than the threshold.
- **A wrong diagnosis, corrected by measuring.** A 279 ms animation frame on a
  4×-throttled runner looked like the ~120-node stage SVG re-rendering on every fit-map
  toggle. Memoising it and measuring gave 86 ms with and 86 ms without, at a 20× throttle:
  the SVG was never the cost, the runner was. The throttle is now 4× locally and 1× on CI.
  The memo is kept as the right default, and its comment says it changed nothing.

### Decisions taken

- ADR-0004 — line height comes from the reference HTML, not from §12.3's table. Tailwind
  preflight's `line-height: 1.5` was making every screen drift downward; this was worth
  1.7 percentage points on 1.1 alone.
- The compact bar is `fixed`, not sticky with a negative margin: inside a flex column the
  negative margin still left the parent's `gap` behind, which pushed every large-title
  screen 10 px down its design.
- Visual comparison is done with pixelmatch against `design/screens` directly, not through
  Playwright snapshots, so nothing in the repo can write into the design pack.
- The feel project runs against a production preview build on its own port. Frame timing
  measured against the dev server is not a number worth having.
- Controls the design draws smaller than 44 px (1.4's "Edit" link is 32 px) keep their
  painted box and gain an invisible 44 px hit area through `.tap-expand`. §12.7's touch
  target is not negotiable; the design's visual is not either.
- ADR-0005 — the visual comparison runs on macOS. On Linux the identical UI lands 1.4 to
  2.4 points further from the baseline purely through glyph rasterisation, so the
  platform moved rather than the threshold.
- Demo mode is compiled out of production builds. `VITE_APP_ENV=production` makes
  `?demo=1` inert and drops the whole fixtures module from the bundle, so Aarav's
  measurements can never be shown to a real user as their own (AGENTS.md rule 9). Two
  components also carried `'Aarav'` as a default prop; both are gone.

### QA pass

Done by hand, because the qa-reviewer subagent hit a rate limit before it reported:

- The visual threshold is still 0.02. Nothing was loosened to make a screen pass.
- Nothing in the repo can write into `design/screens`: the comparison reads the PNGs and
  writes its own output to `test-results/`. Playwright's snapshot mechanism, which had
  already left one stray baseline there, is no longer used.
- No emoji in `en.json` or in any component; the lint rule covers the components and was
  verified to fire.
- A production build contains no `Aarav`, `88% sure`, `Roadster` or `Zudio`.
- `/dev/ui` demos every component in the §12.4 inventory, including the ones whose
  screens arrive later (CameraOverlay, Shutter, AnimatedNumber, Loading, StepList,
  ToolTile, Avatar). Dev builds only.

**Known duplication to clean up:** 2.2 inlines its own step rows rather than using
`StepList`, 3.4 inlines its tool tiles and family avatars rather than using `ToolTile`
and `Avatar`, and 1.3 inlines its camera chrome rather than using `CameraOverlay` and
`Shutter`. The components match the designs and are exercised in the gallery; the screens
were ported from the reference HTML directly and ended up with parallel markup.
Consolidating is safe at the start of the phase that next touches each screen, with that
screen's visual test as the check.
