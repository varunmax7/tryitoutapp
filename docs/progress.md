## Phase 0 — Foundation · **done (local)**, 6 Nov 2026

**Goal:** a working monorepo, CI, local Supabase, Modal skeleton and agent rules.

### What shipped

**Repo and tooling**

- pnpm 10 workspace (`apps/web`, `packages/*`), TypeScript strict everywhere
  (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), ESLint 10 flat config,
  Prettier, Vitest 5, Playwright 1.65, Node 22 in CI. Versions and the two deliberate
  pins are in `docs/decisions/ADR-0001-stack.md`.
- Design guards as lint rules, not conventions (§17.8), verified to fire: raw hex, inline
  durations, inline easing curves and emoji are all errors inside
  `apps/web/src/{ui,features}`.

**apps/web**

- Vite 8 + React 19 + Tailwind v4 + vite-plugin-pwa.
- `src/styles/tokens.css` is §12.2 copied verbatim (and Prettier-ignored, so it stays
  diffable against the plan). Self-hosted WOFF2 for Bricolage Grotesque, Instrument Sans
  and JetBrains Mono — variable axes, subset per unicode-range, regenerated by
  `pnpm fonts:fetch`.
- A route stub for every screen in §12.5 and §12.6, lazily loaded. Sheet-only screens
  (N1, N5, N7, N8, N12) are listed at `/dev/sheets`; `/dev/ui`, `/dev/states` and
  `/dev/sentry` are dev-only and are dropped from production builds.
- `src/app/flags.ts`: the seven §13 feature flags, all `false` in V1, with `?flags=all`
  for the visual tests and `?demo=1` for demo mode.
- PWA manifest with the `/check` share target, `theme_color #0E1726`,
  `background_color #F6F7F9`, `display: standalone`, and an app-shell service worker.
- Cloudflare Pages `_redirects` and `_headers` (CSP, HSTS, `Permissions-Policy:
camera=(self)`, immutable asset caching).

**packages/shared**

- The locked vocabulary from §9 (every Postgres enum) plus the §11.3 confidence banding,
  with the rule that a percentage is only ever shown once a brand × category has ≥ 200
  outcomes **and** the model is calibrated **and** the flag is on.

**apps/worker (Modal)**

- `tryitout_worker/api.py` holds the FastAPI app (no Modal import, so it is testable);
  `app.py` wraps it for `modal serve` / `modal deploy`, scale-to-zero, secret `tryitout`.
- `GET /health` behind Supabase JWT verification against the project JWKS. Asymmetric
  algorithms only — an HS256 token signed with a leaked anon key is refused.
- ruff + mypy strict + 17 pytest tests.

**supabase**

- `supabase init`, `config.toml` set for the project: anonymous sign-ins on, email and SMS
  providers off (§19 step 2.3), redirect URLs for local dev.
- `migrations/0000_health_check.sql` and the public `health` Edge Function, which is what
  the daily keep-alive calls so a Free project never pauses (§19 step 8).

**CI and agents**

- `.github/workflows/ci.yml`: install, lint, typecheck, unit, build, licence check,
  Playwright e2e and visual, plus a worker job on Python 3.11 and a job that fails a PR
  which changes `design/screens` without the `design-change` label (§17.4).
- `health.yml`, `deploy-functions.yml`, `deploy-worker.yml` — each skips cleanly until its
  secrets exist.
- `AGENTS.md`, `CLAUDE.md`, `.claude/agents/*` and `.claude/commands/*` copied verbatim
  from §14.

### What still needs your accounts

None of these can be done from here; each takes a few minutes in a browser.

1. **GitHub** — done: pushed to
   [varunmax7/tryitoutapp](https://github.com/varunmax7/tryitoutapp), and CI is green there.
   Two deliberate differences from §19 step 1 remain: the repo is **public** where the plan
   assumed private, and branch protection on `main` with CI as a required check is not set
   yet, because it would block direct pushes to `main`.
2. **Supabase** — two Free projects in the Mumbai region, `tryitout-staging` and
   `tryitout`. On each: enable anonymous sign-ins and Google, set the Site URL and redirect
   URLs, then add repo secrets `SUPABASE_ACCESS_TOKEN`, `SUPABASE_PROJECT_REF`,
   `SUPABASE_DB_PASSWORD`, and `SUPABASE_URL_*` / `SUPABASE_ANON_KEY_*` for the health job.
3. **Modal** — account with a card on file for the $30/month credit, `modal token new`,
   `modal environment create staging`, and the secret `tryitout` in each environment with
   the keys listed in `.env.example`. Then `MODAL_TOKEN_ID` / `MODAL_TOKEN_SECRET` as repo
   secrets.
4. **Cloudflare Pages** — connect the repo, build command `pnpm --filter web build`,
   output `apps/web/dist`, and set the `VITE_*` variables for preview (staging) and
   production.
5. **Cloudflare R2** — buckets `tryitout-assets` and `tryitout-assets-staging`, a write
   token for the worker, a read-only token for the Edge Functions, CORS allowing GET from
   the Pages domains.
6. **Sentry** — projects `web`, `functions`, `worker`; put the DSNs in the web env,
   function secrets and Modal secret.
7. **Docker Desktop** — needed for `pnpm supabase start` locally. Docker is installed on
   this machine but was not running, so the local stack has not been started yet.

### Decisions taken

- ADR-0001 — stack and version pins (TypeScript 6, not 7, because typescript-eslint caps it).
- ADR-0002 — the licence gate reads `pnpm licenses list` instead of `license-checker`.
- ADR-0003 — Sentry privacy configuration for SDK 11's `dataCollection`.

### Notes for Phase 1

- `tokens.css` is in place; `motion.css`, the type-scale utilities and the §12.4 component
  inventory are Phase 1's first task.
- App icons are a placeholder SVG AppMark. Phase 1 exports the PNG set from the real
  `AppMark` component, which is also what Lighthouse installability needs.
- `src/i18n/en.json` holds only the app name. Phase 1 moves every string from
  `design/reference/*.html` into it.
- The visual baselines are already wired: `snapshotPathTemplate` points at
  `design/screens/{arg}{ext}` with `maxDiffPixelRatio: 0.02`. Never run
  `--update-snapshots` against them (§17.4).
- `HydrateFallback` is deliberately blank until the `Skeleton` component exists (§12.8.10).
